# Ensemble Atelier checks

Build the examples first from repository root:

```bash
python tools/build_ensemble_atelier.py
node --test tests/ensemble-atelier/music.test.cjs
python -m unittest discover -s game-music-composer/scripts/tests -p test_visualize_score.py -v
python -m unittest discover -s game-music-composer/scripts/tests -p test_refine_performance.py -v
```

The Node suite contains 108 tests; the Python extension has 22. They do not replace the canonical release suite.

Optional browser runners require Playwright and an installed Chromium executable. They read `.scratch/ensemble-atelier` by default and write evidence in its `qa/results` folder. Change `GMC_LAB_DIR` for another build and `CHROMIUM_EXECUTABLE` for a different Chromium location. On PowerShell use `$env:GMC_LAB_DIR = '...'` and `$env:CHROMIUM_EXECUTABLE = '...'`; no Python/Node dependency is required by the resulting HTML itself.

```bash
python tests/ensemble-atelier/atelier_tests.py
python tests/ensemble-atelier/index_tests.py
python tests/ensemble-atelier/browser_tests.py
python tests/ensemble-atelier/native_bridge.py
```

Set `GMC_TEST_ID` to I001…I005 to run a single case of the full browser suite. Running separately repeats the registry assertion; counts must not be represented as independent artistic criteria. Browser tests use bundled document content and srcdoc, not a hosted production site or physical mobile devices. The native bridge fixture follows the native JSON shape but is not generated by the original composing engine.

All production approvals, listening comparisons, native sample parity and whole-package checks remain distinct from these tests. Screenshots and WAV outputs are generated evidence, not repository source assets.
